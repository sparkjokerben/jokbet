这些数字是什么What these numbers are

  • 本站 Worker 实时只计不带 Range 的整包 GET；回填的 R2 历史仅在读取字节数等于对象大小时计入。历史上如果 Range 恰好覆盖整份对象，无法与普通 GET 区分。缓存命中、HEAD 和部分续传不计。这里数的是服务端读出，不保证文件已写入访客磁盘。 The live Worker counts a whole-file GET with no Range header; recovered R2 history counts reads whose response bytes equal the object size. A historical Range covering the whole object cannot be told apart from a plain GET. Cache hits, HEAD probes and partial resumes are not counted. This is what the server read, not proof the visitor saved the file.
  • 含应用自动更新：桌宠每次更新自己也是一次下载，它和第一次安装在这里分不出来。GitHub 那半边同样如此。 App updates are in there: the pet fetching its own new build is a download like any other, and it cannot be told apart from a first install — on GitHub's side neither.
  • 同一个人下载两次就记两次：这一页不识别访客，所以也不去重。 The same person downloading twice counts twice: nothing here identifies a visitor, so nothing can deduplicate one.
  • GitHub 的数字每天刷新一次，覆盖每个版本的每个文件；发布流程自己取走的次数、以及签名文件（.sig）上的次数不计入合计 —— 签名是更新器从清单里读的，没有人会单独下载它。 GitHub's numbers are refreshed once a day and cover every file of every release; what publishing the release fetched itself, and what a signature file (.sig) collected, are left out of the total — a signature is read out of the manifest, and nobody downloads one.
  • 日期按 UTC 分日，北京时间要往后加 8 小时。GitHub 那半边没有日期，所以柱子只画本站镜像。 Days are UTC days (Beijing is eight hours ahead). GitHub's half has no days at all, which is why the bars are the mirror's alone.
